How It Works

About This Leaderboard

Two separate voting tracks share this site — Claude Course for Professionals, and the AI Copilot Diploma. They run independently: different projects, different vote rules, different leaderboards.

Two Tracks

Which one am I voting in?

Check the nav bar — each track has its own Vote page and its own Leaderboard.

🏆 Claude Vote

Claude Course for Professionals — final projects, judged by the cohort across four fixed awards: Best ROI, Best Technical, Best Creative, Cohort Choice.

One vote per person, per award. Results stay hidden until the closing ceremony reveal.

💡 AI Copilot Diploma Vote

AI Copilot Diploma, Online and Offline — participants pitch project ideas, and the cohort votes for the one it should actually build and present at graduation.

Vote for as many ideas as you want to support — one vote per idea, toggle any time before voting closes. The top 10 ideas per delivery mode become the official final projects.

Claude Course

Four Awards, One Public Vote

Every project is judged by the cohort itself, on the same information, across four categories.

Instead of separate criteria per category, every project is presented with one identical set of details. Voters read the same card for each project and decide for themselves which project deserves each award — Best ROI, Best Technical, Best Creative, and Cohort Choice.

Why this works: a single consistent format keeps the vote fair — no project is dressed up differently to chase a category — and it's far simpler to build, present, and vote on live during the ceremony.
🏆 Best ROI 🏆 Best Technical 🏆 Best Creative 🏆 Cohort Choice

A voter can give different votes to different projects across categories — e.g. Project A for ROI, Project B for Technical, Project C for Cohort Choice — all from reading the same card.

Section 02 · Claude Course

Voting Mechanics

One card, four vote buttons, real-time tally.

RuleRecommendation
Votes per person / categoryOne vote per person per category — prevents any single voter from dominating a result.
Self-votingDecide upfront whether participants can vote for their own project, and state the rule clearly on the voting page.
Voting windowOpens once all project cards are published; closes shortly before the awards reveal to build suspense.
Project orderRandomized per voter session to avoid a "first project gets more votes" bias.
Before votingVoters are required to view every project card before their first vote is accepted.
Open decisions for you: can one voter pick the same project for more than one category, and can a category have more than one vote per voter? Both should be fixed and stated before voting opens.
Solo-participant risk: since each project is built by one individual rather than a team, Cohort Choice can drift toward "who's well-liked" rather than "best project." Keep the participant photo secondary to the project demo on the card, and frame Cohort Choice as "the project I'd most want to see become real" rather than a popularity pick.
Cohort Choice eligibility: unlike the other three awards, Cohort Choice is limited to a specific roster (managed in Admin — typically the cohort itself). The first time someone votes in that category, they pick their name from the roster; it's then remembered on their device. Best ROI, Best Technical, and Best Creative stay open to anyone.
Section 03 · AI Copilot Diploma

Idea Voting

One card per idea, a vote button on each, and the winners become the cohort's real final projects.

RuleHow it works
Votes per personVote for as many ideas as you want to support — one vote per idea, not one per category. Toggle any idea on or off any time before voting closes.
What winsThe 10 highest-voted ideas per delivery mode (Online and Offline are ranked separately) become that cohort's official final projects for the graduation day.
Who's votableAn admin opens specific cohort intakes for voting — e.g. "Wave 14" or "Online 9" — and only ideas from an open cohort appear. You can browse and filter by cohort, but you can only vote among ideas that are currently open.
ResultsSealed the same way as Claude's — rankings stay hidden until an admin reveals them, enforced at the database, not just hidden in the page.
Why multi-vote: this track isn't judging finished work across categories — it's gauging which ideas the cohort actually wants to build. Letting people back several ideas, not just one, surfaces genuine support rather than forcing an artificial single choice.
Section 04

Live Leaderboard Display

A shared results screen for each track that updates as votes come in.

What It Shows

  • Claude Leaderboard: all projects, ranked live within each of the 4 awards
  • AI Copilot Diploma Leaderboard: Online and Offline ranked separately, top 10 each, shown together on one page
  • A clean "reveal" view for the Claude closing ceremony, projected on screen

Why It Works

  • Builds energy while project demos are still running
  • Keeps the room engaged through every presentation
  • Gives a satisfying, suspenseful moment at results time
Approval step: every project is added by an admin and starts as Pending review. It only becomes visible to voters — and only counts on either leaderboard — once an admin approves it. That's the checkpoint for reviewing each submission before the cohort sees it.
Independent tracks: opening, closing, and revealing Claude never affects the AI Copilot Diploma track, or the other way around — each has its own switches in Admin.
